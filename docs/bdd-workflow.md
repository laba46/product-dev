# BDD-алгоритм для задач портфолио

## Цель

Описывать задачи так, чтобы у результата была проверяемая граница готовности: не "сделай красиво", а "сделай так, чтобы сценарий проходил".

## Где писать сценарии

- Рабочие сценарии: `features/*.feature`.
- Черновики новых задач: сценарии с тегом `@draft`.
- Шаги проверки: `features/step_definitions/*.steps.js`.

## Формат сценария

```gherkin
# language: ru
@draft
Функция: Название продуктовой функции
  Как [роль]
  Я хочу [возможность]
  Чтобы [польза]

  Сценарий: Конкретное поведение
    Дано [исходное состояние]
    Когда [действие пользователя или системы]
    Тогда [ожидаемый результат]
    И [дополнительный проверяемый результат]
```

## Как формулировать

- `Дано` - что уже существует до действия: поставка, документы, статус, ограничения.
- `Когда` - одно главное действие: открыть карточку, загрузить документ, нажать кнопку.
- `Тогда` - видимый и проверяемый результат: текст, статус, список missing items, следующий шаг.
- `И` - дополнительные проверки того же результата, без новой логики.

## Команды

```bash
npm run bdd
npm run bdd:draft
```

`npm run bdd` запускает только рабочие сценарии без `@draft`.

`npm run bdd:draft` запускает черновики. Они могут быть красными или pending, пока мы не реализовали интерфейс и шаги проверки.

## Правило готовности

Задача готова, когда:

- сценарий описывает одно поведение;
- нет приватных данных, внутренних ссылок, ID документов и имен поставщиков;
- шаги можно проверить автоматически или вручную по однозначному признаку;
- после реализации нужные сценарии проходят через `npm run bdd`.
