# DWTECH Shipment Card

Статус: локальный MVP-прототип, версия `v0.2`.

## Зачем этот кейс

Кейс показывает, как операционная проблема импортной поставки переводится в продуктовую сущность: карточку поставки как рабочий центр логиста.

Цель прототипа — доказать не HTML-навык, а PM-цепочку:

`user story -> функциональность -> проверяемый интерфейс`.

## Что покрывает v0.2

| User story | Функциональность в интерфейсе |
| --- | --- |
| `US-01` Логист за 1 минуту оценивает комплектность документов | Блок комплектности, missing items, следующее действие, заблокированная отправка агенту при неполном комплекте |
| `US-02` Логист видит этапы, историю обмена и сторону следующего шага | Workflow, текущий этап, next owner, activity log |
| `US-03` Логист понимает структуру сложной отгрузки | Тип отгрузки, позиции, остатки, роли плательщика и фактического отправителя |

## Как открыть

Открыть локально:

```text
cases/dwtech-shipment-card/index.html
```

Или запустить локальный сервер из корня репозитория:

```bash
npx http-server . -p 4173
```

## Проверка

BDD-сценарии лежат в `features/shipment-card.feature`.

```bash
npm test
```

## Design artifacts

Публично-безопасная копия Pencil-wireframe лежит в:

```text
cases/dwtech-shipment-card/artifacts/supply-card-wireframe-2026-09-15.sanitized.pen
```

Файл сохранен как snapshot итерационного workflow: сначала пространственная структура и зоны, затем компоненты, затем локальные визуальные итерации.

## Публикационная безопасность

В прототипе используются обезличенные данные: нет реальных поставщиков, внутренних ссылок, ID документов, credentials и локальных путей.
